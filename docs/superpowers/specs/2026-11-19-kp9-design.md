# kp9 — Cliente HTTP TUI estilo k9s (diseño)

Fecha: 2026-11-19
Estado: borrador para revisión

## 1. Objetivo

Herramienta de terminal **personal** que permite administrar y ejecutar endpoints HTTP
como Postman, con la estética y navegación de **k9s** (teclado primero, vistas por
recurso, barra de comandos `:`).

**Criterio de éxito:** importo mis colecciones de Postman, cambio de entorno y
ejecuto/reviso requests sin abrir Postman. Las colecciones son archivos JSON que puedo
versionar en git si quiero (opcional).

### Alcance MVP

- Workspace en archivos JSON versionables en git.
- Jerarquía **Grupo → Colección → Carpeta → Request**.
- Entornos y variables `{{var}}`, con secretos fuera del repo.
- Auth: Bearer, Basic, API Key, OAuth2 client credentials.
- Historial de ejecuciones navegable y re-ejecutable.
- Importación de colecciones y entornos Postman v2.1.

### Fuera del MVP

Scripts pre-request y tests, runner de colecciones, exportación a Postman,
GraphQL/gRPC/WebSocket, filtro `jq` sobre la respuesta, editor de formularios propio.

## 2. Stack

- **Python 3.11+**, gestionado con **uv** (`pyproject.toml`, lockfile).
- **Textual** para la TUI (tablas, barra de comandos, CSS de temas, async nativo).
- **httpx** (async) para ejecución HTTP.
- **pydantic v2** para el modelo y validación del workspace JSON (errores con ruta del campo).
- `sqlite3` de la librería estándar para historial.
- **watchfiles** para recargar ante cambios externos.
- **Typer** para los subcomandos de CLI.

## 3. Modelo de datos y almacenamiento

### 3.1 Estructura del workspace

```
<workspace>/
├─ workspace.json                 nombre, grupo por defecto, config
├─ environments/
│  ├─ dev.json
│  ├─ qa.json
│  └─ prod.json
├─ groups/
│  └─ <grupo>/
│     ├─ group.json               descripción, auth y variables heredables
│     └─ <coleccion>/
│        ├─ collection.json       baseUrl, auth, variables de colección
│        ├─ folder.json           (opcional, en cada carpeta) auth/variables de carpeta
│        └─ <carpeta>/
│           └─ <request>.json     un archivo por request
└─ .kp9/                          local, agregado a .gitignore
   ├─ secrets.json                valores secretos por entorno
   └─ history.db                  historial SQLite
```

- Un directorio dentro de una colección es una carpeta; puede anidarse sin límite.
- Los nombres de archivo/directorio son slugs (`agregar-al-carrito.json`); el nombre
  visible está en el campo `name`.
- Todos los nodos admiten `"description"` (JSON no admite comentarios).

### 3.2 Request

```json
{
  "name": "Agregar al carrito",
  "description": "Agrega un SKU al carrito activo",
  "method": "POST",
  "url": "{{baseUrl}}/v1/cart/items",
  "params": { "channel": "web" },
  "headers": { "Content-Type": "application/json" },
  "body": { "type": "json", "content": { "sku": "{{sku}}", "qty": 1 } },
  "auth": { "type": "inherit" }
}
```

- `body.type`: `none` | `json` | `text` | `form-urlencoded` | `multipart`.
- `auth.type`: `inherit` (por defecto) | `none` | `bearer` | `basic` | `apikey` | `oauth2-cc`.

### 3.3 Auth

```json
{ "type": "bearer",    "token": "{{token}}" }
{ "type": "basic",     "username": "{{user}}", "password": "{{pass}}" }
{ "type": "apikey",    "key": "X-Api-Key", "value": "{{apiKey}}", "in": "header" }
{ "type": "oauth2-cc", "tokenUrl": "{{authUrl}}/token", "clientId": "{{cid}}",
  "clientSecret": "{{csecret}}", "scopes": ["read"] }
```

`apikey.in`: `header` | `query`.

### 3.4 Entornos y secretos

```json
{
  "name": "prod",
  "protected": true,
  "variables": {
    "baseUrl": "https://api.example.com",
    "token": { "secret": true },
    "cid": "$ENV:KP9_PROD_CLIENT_ID"
  }
}
```

- `{ "secret": true }` declara la variable; su valor vive solo en
  `.kp9/secrets.json` (`{ "prod": { "token": "..." } }`).
- `$ENV:NOMBRE` toma el valor de una variable de entorno del sistema.
- Un entorno es **protegido** solo si declara `"protected": true` (opt-in).

### 3.5 Resolución (herencia)

**Variables** (como en Postman, el entorno activo manda; cambiar de entorno siempre cambia
`baseUrl` y demás valores):

**entorno activo > carpeta(s) (de la más interna a la externa) > colección > grupo**

Las variables de grupo/colección/carpeta funcionan como valores por defecto cuando el
entorno no define la variable.

**Auth**: gana la capa más específica: **request > carpeta(s) (interna→externa) > colección > grupo**.

`auth: inherit` sube por la jerarquía hasta encontrar un auth definido; si no hay, `none`.
Una variable sin valor tras resolver todas las capas es un error (no se envía el request).

### 3.6 Importación Postman

`kp9 import <coleccion.json> --group <grupo> [--env <entorno.json>...]`

- Carpetas Postman → directorios; requests → archivos JSON.
- Variables de colección → `collection.json`; auth de colección/carpeta/request se mapea.
- Variables de entorno de tipo `secret` → `.kp9/secrets.json`.
- Elementos no soportados (scripts, tests, auth no soportadas) se omiten y se listan en
  un resumen final; la importación no aborta.

## 4. Vistas y navegación

### 4.1 Layout

```
┌ Workspace: mis-apis        Env: <qa>   Grupo: pagos ─────── atajos ┐
│ <1> grupos  <2> colecciones  <e> env  <h> historial  <?> ayuda     │
├─ Requests(pagos/checkout-api/carrito)[3] ───────────────────────────┤
│ METHOD  NAME                URL                         LAST        │
│ POST    Agregar al carrito  {{baseUrl}}/v1/cart/items   201 · 120ms │
│ GET     Ver carrito         {{baseUrl}}/v1/cart         200 ·  85ms │
├─────────────────────────────────────────────────────────────────────┤
│ <grupos> <checkout-api> <carrito>                     ← breadcrumbs │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 Vistas

| Vista       | Contenido                                        | `Enter`                    |
|-------------|--------------------------------------------------|----------------------------|
| Grupos      | grupos y n.º de colecciones                      | abre colecciones           |
| Colecciones | colecciones del grupo                            | abre carpetas/requests     |
| Requests    | carpetas y requests (carpetas navegables)        | abre detalle               |
| Detalle     | pestañas Params/Headers/Body/Auth + respuesta    | —                          |
| Entornos    | entornos y variables (secretos como `••••`)      | activa entorno             |
| Historial   | ejecuciones: fecha, método, URL, status, tiempo  | ver respuesta; `r` re-ejecuta |

### 4.3 Comandos `:` (con autocompletado)

`:groups`, `:col <nombre>`, `:env <nombre>`, `:history`, `:import <archivo>`, `:q`.

### 4.4 Atajos

| Tecla            | Acción                                   |
|------------------|------------------------------------------|
| `/`              | filtrar tabla / buscar en body           |
| `Esc`            | volver / cancelar request en curso       |
| `s` / `Ctrl-R`   | enviar request                           |
| `n` / `e` / `d`  | crear / editar / borrar (con confirmación) |
| `c`              | copiar request como `curl`               |
| `y`              | copiar body de respuesta                 |
| `?`              | ayuda                                    |

### 4.5 Edición

`e` abre el archivo JSON (request, entorno, colección, grupo) en `$EDITOR`
(fallback `vi`). Al cerrar se valida y recarga. `n` crea un archivo con plantilla y lo
abre en el editor.

### 4.6 Respuesta

Status, tiempo, tamaño, headers y body con pretty-print y resaltado para JSON.

### 4.7 Protección de entornos

Con entorno protegido: barra superior en rojo y confirmación obligatoria antes de enviar
POST/PUT/PATCH/DELETE.

## 5. Arquitectura

```
src/kp9/
  cli.py              Typer: subcomandos (tui por defecto, init, import)
  model.py            modelos pydantic del dominio
  store.py            carga/guarda workspace JSON; watcher (watchfiles)
  resolve.py          herencia + sustitución de {{variables}}
  secrets.py          secrets.json y $ENV:
  auth.py             bearer, basic, apikey, oauth2-cc (cache de token en memoria)
  httpclient.py       ejecuta request resuelto → Response (httpx async)
  history.py          persistencia SQLite y consulta
  redact.py           redacción de headers sensibles y secretos
  importer/postman.py Postman v2.1 → model
  tui/
    app.py            App Textual, router de vistas, barra de comandos
    views/            una vista por archivo (groups, collections, requests, detail, envs, history)
    kp9.tcss          estilos (tema estilo k9s)
tests/
```

- `tui` depende solo de las interfaces públicas de `store`, `resolve`, `httpclient`, `history`.
- `resolve` es puro (sin IO): recibe el árbol del modelo + entorno + secretos.

### 5.1 Flujo de envío

1. `resolve` fusiona capas y sustituye variables → `ResolvedRequest`.
2. `auth` aplica credenciales (OAuth2: obtiene token y lo cachea hasta expiración).
3. Si el entorno es protegido y el método no es GET/HEAD/OPTIONS → confirmación.
4. `httpclient` ejecuta en un worker async de Textual con timeout (30 s por defecto,
   configurable en `workspace.json`); `Esc` cancela el worker. La UI muestra spinner sin
   bloquearse.
5. Se muestra la respuesta y se guarda en `history` tras **redactar** headers sensibles
   (`Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key` + lista configurable) y
   cualquier valor de secreto presente en URL, headers o body.

## 6. Manejo de errores

| Caso                          | Comportamiento                                                   |
|-------------------------------|------------------------------------------------------------------|
| Variable no definida          | no se envía; mensaje `{{sku}} no definida en qa` + atajo a editar entorno |
| JSON inválido al cargar       | ítem marcado ⚠ con archivo:línea:columna; el resto funciona      |
| JSON inválido tras editar     | muestra el error y ofrece reabrir el editor                      |
| Red / TLS / timeout           | error en panel de respuesta; registrado en historial como fallido |
| Fallo de token OAuth2         | error con status y body del token endpoint (redactado)           |
| Importación parcial           | resumen de lo omitido; no aborta                                 |
| Cambio externo (git pull)     | recarga en caliente conservando la vista actual                  |

## 7. Testing

- **Unitario:** `resolve` (orden de herencia, variables faltantes), `secrets` (no fuga),
  `auth` (cada tipo, cache OAuth2), `importer/postman` con golden files.
- **Integración:** `httpclient` + `auth` con **respx** (mock de httpx: timeouts,
  cancelación, errores de red, redacción en historial); `history` con SQLite en
  `tmp_path`.
- **TUI:** `App.run_test()` + `Pilot` de Textual para flujos críticos: navegar
  Grupo→Request, enviar, confirmación en entorno protegido, filtro `/`.
- **Herramientas:** `pytest`, `pytest-asyncio`, `ruff` (lint + formato), `mypy`.

## 8. Distribución

- Instalación local: `uv tool install --editable .` desde el repo; expone el comando `kp9`.
- Requiere Python 3.11+ (uv lo instala automáticamente si falta).
- `kp9 init` crea la estructura base del workspace y el `.gitignore` con `.kp9/`.
- Sin CI ni releases en el MVP; los checks (`pytest`, `ruff`, `mypy`) se corren localmente.
